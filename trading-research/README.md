# Trading research: which of my rules actually have an edge?

I day trade Nasdaq futures (NQ and MNQ). This project is my attempt to answer one question with data instead of opinion: **do the rules I trade make money over many years, or only on the charts I remember?**

The short answer is that most of them don't. Of more than fifteen rules tested, one survived out-of-sample testing. Everything is logged, including every failure.

> Backtest results are hypothetical. They use one MNQ contract with $1 commission per side and one tick of slippage per order. Nothing here is investment advice.

## Method

1. **Write the rule down first.** Each rule is specified before it is run, with its acceptance test: positive in at least 6 of 8 calendar years and at least +0.05 R per trade (R = the amount risked on the trade).
2. **Test in TradingView.** The Pine strategy runs in the Strategy Tester and the list of trades is exported.
3. **Rebuild the rule in Python.** A local engine replays the same rule bar by bar on seven years of 1-minute and 5-minute CME data. It is calibrated against TradingView before it is trusted: for the opening range breakout, 818 of 820 trades matched.
4. **Split the data.** Settings are chosen in-sample and then run once on data the search never saw. A change that helps in-sample and hurts out-of-sample is treated as overfitting and reverted.
5. **Check that a filter isn't luck.** Splits are compared against shuffled labels, and a result found after testing many filters is not trusted on its p-value alone.
6. **Test my own judgment the same way.** Blind chart reviews (charts cut off at the decision bar, answers scored against a hidden key) measure whether my discretionary calls beat chance.

## Results

| Rule | Outcome | Evidence |
|---|---|---|
| ICT SMT + IFVG (the indicator's signal) | **Rejected** | +$3,105 on the year it was tuned on. The same settings lost on the prior year (−$2,028) and on the S&P contract. Rebuilt in Python over seven years: 773 trades, −0.11 R per trade, 2 of 8 years positive. |
| Opening range breakout (v1.3) | **Survived** | June 2019 to September 2026: 875 trades, +$21,000, profit factor 1.27, 50% winners, +0.13 R per trade, worst drawdown −15 R, two losing years. Out-of-sample the edge is smaller (profit factor 1.12) but still positive. Now in a forward test. |
| Overnight value-area 80% rule | Rejected | Looked good for three years, failed out-of-sample, and made the breakout rule worse when combined with it. |
| VWAP reversion, overnight-extreme rejection, lunch-range breakout, gap fill | Rejected | None met the acceptance test. |
| ICT AMD, order block, order block + IFVG, optimal trade entry, 10:00 "Powell" model | Rejected | One pre-registered run each, several variants. None met the acceptance test. |
| Walk-forward parameter search on the breakout rule | Nothing adopted | 1,536 combinations searched in-sample. None beat the existing settings out-of-sample, so the settings were left alone. |
| Economic-event filters | Not adopted | Retail-sales days look bad for the breakout rule (p = 0.011), but 18 event types were tested, so that p-value does not survive a multiple-comparison correction. It is tracked in the forward test, not traded. |

Full detail for every row is in [`BACKTEST_LOG.md`](BACKTEST_LOG.md).

## What I learned

- **A profitable backtest on one year means very little.** My original signal made money on the year I tuned it on and lost on every other sample. In the log's words: the year, not the filter, decided the result.
- **More filters is usually more overfitting.** Several filters helped in one half of the data and hurt in the other. With 93 trades, any of them would have been curve fitting.
- **Calibrate the simulator before believing it.** Matching the Python engine to TradingView trade by trade caught a wrong default in my own script.
- **The edge lives in the tail.** For the breakout rule the median trade is about zero and the profit comes from the top 5% of trades, so skipping trades selectively is dangerous.
- **Size from risk, not from past dollars.** The typical stop distance quadrupled between 2019 and 2026, so old dollar drawdowns understate today's risk.
- **Count how many things you tested.** A p-value of 0.011 is not convincing when it is the best of 18 tries.

## The indicator

`ICT_SMT_IFVG.pine` marks a specific setup on the chart: a divergence between two correlated index futures (one makes a new extreme, the other doesn't) followed by an inverted fair value gap inside a higher-timeframe gap.

- **One engine, many timeframes.** The whole detector is a single function, `f_runEngine(Engine e, Feed f)`. A `Feed` is the closed candles of one timeframe for both markets, and an `Engine` holds that timeframe's state. The same code therefore runs on the chart timeframe and on up to four higher timeframes at once.
- **No repainting.** Every decision uses closed bars only, so a signal never changes after it prints.
- **Position sizing built in.** Contracts = account risk ÷ (stop distance in points × point value).
- **Built to explain itself.** A debug table and tooltips say why a setup did or did not produce a signal.

Pine Script caps a script at 550 local scopes and 80,000 compiled tokens. The file sits just under both, which shaped several design choices described in [`INDICATOR.md`](INDICATOR.md).

## Running the tools

The Python tools need `pandas`, `numpy`, `matplotlib` and `pyarrow`. They read bar data from `data/bars/`, which is not in the repository because the market data is licensed (CME data from Databento). With your own data in place:

```bash
python3 tools/build_bars.py MNQ_ohlcv1m.dbn.zst MNQ       # raw data -> 1m and 5m Parquet bars
python3 tools/orb_engine.py --start 2019-06-01 --out t.csv # run the breakout rule locally
python3 tools/split_check.py t.csv                         # years positive, R per trade, splits
python3 tools/calibrate_orb.py export.csv                  # compare with a TradingView export
python3 tools/wf1.py                                       # walk-forward search (about 6 minutes)
```

The Pine scripts run in TradingView: paste a file into the Pine editor and add it to a chart.

## How this was built

I built this with an AI coding tool (Claude). The trading rules, the definitions of each setup, the decision to pre-register runs and the calls on what to keep or drop are mine. The AI wrote most of the Pine and Python code and ran the analyses. I reviewed the results, answered the blind chart studies myself, and used the project to learn how backtesting goes wrong.
